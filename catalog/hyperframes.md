# hyperframes

**Purpose:** Route video/composition requests to the appropriate HyperFrames workflow and project brief.

**Invocation:** automatic

**Use when:** The deliverable is a video, motion graphic, interactive deck or change to an existing HyperFrames project.

**Do not use when:** Animating an interactive app button, general UI redesign, or ordinary research with no video/deck deliverable.

**Overlaps and default:** Read first for fresh HyperFrames creation. Short unnarrated motion-first units lead to motion-graphics; general-video is a fallback, not the owner of every long video. Specialized caption, product-launch and other workflows live in the bundled support tree.

**Requirements:** Deliverable brief, source material and existing project state. Actual production requires the CLI/runtime described by hyperframes-cli. Read only the selected route and its supporting files; follow toolkit update and local-render rules.

**Expected output:** An appropriate workflow and brief/handoff, or continuation of the existing project workflow.

**Positive example:** "Turn this product launch into a video; choose the right production workflow."

**Negative example:** "Animate the save button inside our web app."
