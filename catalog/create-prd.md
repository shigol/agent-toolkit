# create-prd

**Purpose:** Create a lean product requirements document that supports a decision about the first version.

**Invocation:** automatic

**Use when:** The user needs a PRD, feature specification or review of an existing requirements document.

**Do not use when:** A routine bug fix, implementation already specified, a whole-company strategy or general research with no requirements deliverable.

**Overlaps and default:** product-strategy sets broader direction; north-star-metric defines measurement; this turns a scoped initiative into requirements. Humanizer can later edit wording without changing decisions.

**Requirements:** Problem, target users and success criteria from available context. Ask only for missing information the user owns; research public facts when helpful. Mark assumptions. The optional external value-proposition skill is not registered here.

**Expected output:** A concise PRD with segments, value propositions, scope and open questions, or a focused review of an existing PRD.

**Positive example:** "Write a lean PRD for the onboarding improvement using this research."

**Negative example:** "Fix the already-specified validation bug in the onboarding form."
