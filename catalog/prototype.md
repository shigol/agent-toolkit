# prototype

**Purpose:** Build distinct variants of one UI component in an isolated visual comparison surface.

**Invocation:** explicit-only

**Route:** Compare disposable UI prototypes

**Synonyms:** UI variants; disposable prototype; compare interactions; parallel UI directions

**Use when:** The user explicitly invokes prototype to explore several working answers to a component brief.

**Do not use when:** A routine implementation, minor color variations, production changes before a variant is chosen, or an entire app redesign in one run.

**Overlaps and default:** Impeccable handles general design work; this specializes in live comparison of one UI piece. It is not automatically triggered by any request mentioning alternatives.

**Requirements:** Explicit invocation, component brief, project tokens and a runnable preview. Use PICKER.md. Keep production code untouched during exploration; promote the user-selected variant afterward.

**Expected output:** An isolated picker containing working, meaningfully different variants and a later chosen integration.

**Positive example:** "Use prototype to compare three different pricing-card interaction models."

**Negative example:** "Implement the approved pricing card exactly as designed."
