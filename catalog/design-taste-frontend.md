# design-taste-frontend

**Purpose:** Develop a distinct visual direction using researched compositions, typography, palettes and browser inspection.

**Invocation:** explicit-direction

**Route:** Alternative visual direction

**Synonyms:** alternative visual direction; art direction; distinctive frontend; premium interface

**Use when:** The user explicitly chooses an alternative art direction or requests Taste. It supports both public pages and working app screens, with different workflows.

**Do not use when:** Routine UI maintenance, a request that must preserve the existing direction, backend work or automatic restyling just because a page is mentioned.

**Overlaps and default:** Impeccable remains the default. Taste owns an alternative direction when selected; its app-screen workflow applies to dashboards and editors. Project brand and product requirements still win.

**Requirements:** A real brief, available assets and target implementation. Scripts require Node 22+ and Chrome/Edge/Chromium; asset search needs network access. Follow references/app-screens.md for app screens.

**Expected output:** A chosen direction, implemented page or screen, and screenshot/inspection findings.

**Positive example:** "Explore a deliberately different editorial direction for this landing page."

**Negative example:** "Adjust the spacing in our existing settings screen without changing its style."
