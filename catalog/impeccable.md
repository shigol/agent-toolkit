# impeccable

**Purpose:** Plan, build, critique or refine an interface around its users, task and existing product identity.

**Invocation:** automatic

**Route:** UI design or polish

**Use when:** A screen needs better hierarchy, layout, typography, accessibility, onboarding or overall visual quality.

**Do not use when:** Backend-only changes, factual research, video production, or a narrow frame-rate diagnosis.

**Overlaps and default:** Default for general UI work. Use emil-design-eng for component detail after the direction is established, animation-performance for dropped frames, and Taste only for an explicitly chosen alternative direction. Do not combine two full art-direction workflows.

**Requirements:** Project brief, current design rules and target screen/code. Run the pinned context launcher; if unavailable, follow its documented direct-context fallback. Rendered verification needs a runnable surface or identified, current visual evidence.

**Expected output:** A scoped design plan, critique or implemented UI, with visual checks appropriate to the request.

**Positive example:** "This dashboard feels dated; improve its hierarchy while keeping our design system."

**Negative example:** "Fix the API authentication failure; there is no UI change."
