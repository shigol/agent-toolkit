# emil-design-eng

**Purpose:** Refine component details, interaction behavior and animation decisions within an established design direction.

**Invocation:** automatic

**Route:** UI component behavior and feel

**Use when:** An existing component feels awkward despite functioning correctly, or needs focused design-engineering review.

**Do not use when:** A whole new art direction, unrelated backend review, video production or Swift language guidance.

**Overlaps and default:** Impeccable is the general UI default. Prefer narrower Emil skills when the task is specifically animation construction, performance, Sonner or mobile browser behavior.

**Requirements:** Target component, code, existing tokens and expected behavior. Render or interact with the component when assessing visible behavior; label code-only findings.

**Expected output:** A focused component implementation or review covering interaction details, motion and accessibility.

**Positive example:** "Polish this combobox: focus, keyboard behavior, interruption and visual feedback."

**Negative example:** "Estimate the addressable market for a new analytics product."
