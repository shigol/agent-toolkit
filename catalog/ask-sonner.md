# ask-sonner

**Purpose:** Configure and debug the Sonner React toast library using its documented APIs.

**Invocation:** automatic

**Route:** Toast notification behavior

**Synonyms:** Sonner; Toaster; toast notification; promise toast; toast styling

**Use when:** A project uses or explicitly intends to use Sonner, and needs Toaster setup, toast behavior, styling or troubleshooting.

**Do not use when:** Notifications in an unrelated library, choosing a whole UI stack, or a general product redesign.

**Overlaps and default:** Prefer this over general animation/design advice for Sonner-specific behavior. pick-ui-library is a separate manual-only library-selection workflow.

**Requirements:** React project/package context and the Sonner version/configuration. Read the bundled API.md for precise props and defaults; verify behavior in the target app.

**Expected output:** A Sonner-specific explanation, configuration or fix.

**Positive example:** "Our Sonner promise toast appears twice and loses its dark-mode styling."

**Negative example:** "Redesign the notification strategy across email, push and the product."
